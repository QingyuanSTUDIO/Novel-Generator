# 叙事工坊（Novel Generator）

叙事工坊是一个本地优先的 Electron 桌面小说创作工作台。它把章节正文、世界书、角色卡、道具卡、技能卡、大纲、世界引擎、文风规则、自定义 JSON 模块和网络热梗放在同一套创作流程里，再通过可审阅的 AI Agent 辅助维护作品。

当前产品入口是独立桌面窗口。Vue 3 + TypeScript + Vite 负责界面，Electron 负责窗口和作品集文件读写，本机 Node HTTP 服务负责软件配置与工作记录持久化、模型代理和联网搜索。Vite 浏览器页面仍可用于开发调试，但不是日常使用入口。

## 启动

在项目根目录执行：

```bash
npm install
npm run desktop:dev
```

`desktop:dev` 会启动 Vite 开发服务和 Electron 独立窗口。需要验证构建产物时使用：

```bash
npm run desktop
```

也可以双击根目录的 `start.bat`。脚本会检查 Node.js 和 npm，在缺少 Vite 或 Electron 时安装依赖，然后构建并启动桌面版。

常用开发命令：

```bash
npm run build   # 类型检查并构建前端
npm test        # 运行 Node 测试
npm run server  # 单独启动本机 Node 服务，主要用于调试
```

## 当前功能

### 开始写作

- 章节和分卷管理，支持章节搜索、快速跳到头章或末章，以及卷的展开 / 折叠。
- 正文编辑、自动保存、专注写作和保存状态提示。
- 本章任务、出场人物标签、正文生成 API 选择。
- 生成候选正文时支持流式显示；候选需要作者采纳后才覆盖正文。
- 按段落拆分正文，选段后可让 AI 读取章节上下文、检索资料和文风规则进行修改，再由作者采纳结果。
- 提供格式化工具和纯文本复制，复制整章时会去掉 Markdown 首位符号等格式标记。
- 页面底部提供可折叠、可拖动调整高度的控制台，可查看任务步骤或使用真实终端。

### 创作空间

- **世界书**：条目支持常驻 / 关键词触发、触发键标签、注入排序、递归和进一步递归开关。
- **角色卡**：角色身份（主角 / 配角 / 路人）、性别、种族、性格、外貌、角色信息、动态状态、持有道具和持有技能；支持 9:16 角色图片、多图管理、裁切、设为封面和删除。
- **道具卡**：用途、持有人、位置、限制、正文证据和相关线索等结构化字段。
- **技能卡**：技能性质只有主动 / 被动两种，技能效果支持可伸缩输入和标签式增量编辑。
- **自定义模块**：用字段定义创建自己的 JSON / 表格结构，支持文字、长文本、数字、枚举、布尔、标签，以及角色 / 道具 / 技能索引字段；索引可以直接关联现有卡片。
- **网络热梗**：独立的热梗表，可手动维护，也可让 Agent 联网搜索、分批整理、去重和提炼后直接写入，不会误写成世界书条目。
- 世界书、角色、道具、技能和文风规则都支持折叠栏、拖动排序、条目拖放分组、一键折叠 / 展开；折叠栏可由 Agent 创建、删除和调整条目归属。
- 标准卡支持 Agent 创建 / 手动创建、待修改 / 完成状态、字段小锁和整条目大锁。锁定内容不会被 Agent 改写。

### 全局把握

- **故事大纲**采用“全书 → 卷 → 章节范围 → 场景”的嵌套树，父子层级有约束，卷和节点都可以折叠。
- **世界引擎**读取大纲、正文、世界书、角色、道具和技能的检索结果，按当前、按章、按天、按月或自定义天数推进故事时间，生成世界局势、后台行动、事件、关系、时间线和工作笔记。
- 世界引擎可以单独选择推演 API。模型输出先作为待确认提案，作者确认后才会写入正式状态；伏笔数据已经统一由大纲和世界引擎管理。

### AI 功能

- AI Agent 有**写作模式**和**灵感模式**。写作模式会注入启用的文风规则，灵感模式用于讨论和发散，但仍然读取作品资料。
- Agent 返回严格 JSON 操作协议，先显示修改计划，再由作者确认执行；支持创建 / 更新 / 删除标准卡、章节、分卷、自定义模块及条目、世界引擎事件、文风规则和折叠栏。
- Agent 可以联网搜索网络热梗，支持 Bing、Google 和 DuckDuckGo，搜索结果会经过关键词拆分、分批搜索、整理和提炼。
- 悬浮球可以自由拖动，Agent 面板会跟随悬浮球；独立 Agent 页面支持新建、重命名、归档、恢复和删除对话。
- Agent 对话、归档、活动记录、修改记录和撤销记录保存在本机 profile，按作品集与作品分别恢复。执行中的行为会显示在活动条和“AI 刚刚做了什么”日志里。
- **控制台**有独立页面，显示任务队列、执行步骤、返回结果和待确认计划，支持批准、暂停、继续和终止。桌面 Agent 与 CLI 共用审批、字段锁、撤销记录和统一 `.qy` 保存。
- 终端视图可以运行真实的 PowerShell、cmd 和本机已安装的 Codex 命令；终端输出与任务步骤日志分开，任务日志不包含全部 Electron 启动 stderr。
- **MCP 连接**位于右上角设置，默认关闭、默认本机端口 `43127`。外部客户端可读取资料、检索、调用内置 Agent 或自行提交计划；提供 HTTP / stdio 接入与 Codex、Claude Code、DSH、Zcode 配置模板，修改仍在桌面端审核。
- 标题栏“已保存”左侧显示 **MCP 未连接 / 已连接**：未连接红灯，检测到认证成功的客户端活动后绿灯，文字及状态灯均跟随外观设置。仅启动服务不会显示已连接。

### 全局功能与 Debug

- **文风规则**是作品集级创作内容，同一作品集中的作品共享规则并随 `.qy` 保存，支持启用开关、折叠栏、拖动排序、正例 / 反例和整体强化提示词。写作模式的正文、世界书、角色、道具、技能和自定义模块创建都会读取启用的规则。
- **上下文编排**是两级提示词布局：先排大类，再排大类中的资料项。世界书、角色、道具、技能、文风、大纲、世界引擎和自定义模块都可以启用、禁用、折叠和拖动排序，顺序就是发送给模型的提示词顺序。
- 上下文区域会随着内容变动重新估算 token，显示本地预算、已用量和剩余量；服务端实际返回的输入、输出、缓存命中等 usage 会单独显示，未返回的数据保持未知。
- **JSON 结构查看器**展示标准卡、世界引擎、上下文检索包、Agent 请求包和 Agent 操作协议的通用格式。

## API 与模型

右上角设置面板管理 API 预设。每个预设包含协议、地址、密钥、模型、上下文长度、最大输出、历史预算、流式输出、温度、Top P、频率惩罚、存在惩罚和上游代理设置。

当前协议枚举包括：

- `OpenAI Compatible`（默认）
- `Anthropic`
- `Google Gemini`
- `自定义 HTTP`

模型通过“获取模型”从当前预设的服务器拉取，并在下拉栏中选择。连接测试、模型上限查询和正文 / Agent / 世界引擎请求都经过本机 Node 服务；桌面窗口不会直接跨域访问中转站。API 预设可以单独启用一个作为默认 API，Agent、正文和世界引擎也可以分别选择预设。

启用“使用代理”后，本机 Node 服务按代理地址和端口访问上游服务。它只影响上游出口，不会把本机存储请求发到浏览器代理。流式开关控制正文和 Agent 是否逐段显示；流式 usage 统计取决于上游是否提供对应字段。

上下文长度是本地预算，默认值为 272,000 Tokens。它不会扩大服务端限制。发送前会为最大输出和安全余量预留空间，并按完整消息轮次裁剪历史；中文 token 数是估算值，模型上限查询能返回元数据时会采用更保守的输入预算。Anthropic 不发送它不支持的惩罚参数。

## 作品文件与持久化

### `.qy` 作品集文件

`.qy` 是版本化 JSON **作品集文件**，一个文件可以保存多部作品。桌面端当前已经使用 v2 作品集读写；旧版 v1 单作品文件会被明确拒绝。完整产品强化顺序见[产品强化路线](docs/product-roadmap.md)，`.qy` 的数据改造细节见[`.qy` 作品集文件路线](docs/qy-portfolio-roadmap.md)。

当前格式包含：

- 作品集元数据和多个作品项目；
- 每个作品的章节、分卷和正文；
- 每个作品的世界书、角色卡、道具卡、技能卡；
- 每个作品的大纲、世界引擎状态和提案；
- 每个作品的自定义模块、网络热梗和上下文编排；
- 作品集级别的文风规则。

当前加载的 `.qy` 是作品实时内容的唯一持久化位置。正文区保存、文件菜单保存、自动保存、操作前保存保护和关窗刷盘使用同一串行队列，写入全部作品及共享文风；切换作品不会换掉作品集路径。“已保存”以当前作品集写入完成为准。

没有 `.qy` 路径时，显式保存、保存保护中的“保存并继续”和关窗保存会打开文件选择框。自动保存不会弹框，尚未写入文件的作品内容继续保持未保存状态；取消首次保存会留在应用中，不会被当成保存失败。

`.qy` 不包含 API 预设、模型列表、主题颜色、自动保存间隔、备份数量等软件级设置。这些设置保存在 Electron 应用数据目录中的 profile，并在打开其他作品集时继续使用。文件菜单区分“新建作品集”和“新建作品”：前者建立新的作品集，后者只在当前作品集内新增项目。保存前会按设置轮转备份，最近作品集最多保留 30 条记录。

在 **设置 → 作品文件** 查看当前 `.qy`、实际保存 / 备份目录，以及当前作品集的备份时间、名称、大小和作品数量。目录可以直接打开，损坏备份显示错误并禁用恢复。备份池按完整路径区分，数量 `0` 表示不保留；旧备份只在保存成功后裁剪。

“恢复为新作品集”只生成新 `.qy`，不会覆盖原文件、备份或已有目的文件，也不会切换当前编辑。副本保留内容及内部关联，重新生成作品集和作品 ID；需要使用副本时点击“打开恢复的作品集”，未保存编辑仍经过保存保护。

保存会检查磁盘文件版本。外部修改、删除或目的文件被新建时，显示 **文件冲突**，暂停自动写入，并提供另存为、重新加载磁盘版本或取消保留编辑。重新加载会放弃未保存编辑；读取期间出现新的编辑时拒绝替换。另存为期间新增编辑会继续写入新副本，后续保存失败仍可重试。文件版本检测不提供跨进程文件锁或自动合并。

Agent 对话、归档、活动日志、修改历史和撤销快照也只保存在本机 profile，使用 `portfolioId:projectId` 隔离，不写入 `.qy`。迁移作品集不会自动带走这些工作记录。生成保存快照时，相同的聊天内容和活动记录不会重复触发未保存状态。

控制台任务和步骤事件另存于 `console-jobs.json`，最多保留 200 个任务、每任务 200 个事件，不写入 `.qy`。重启不自动重跑任务，已有计划需要确认，暂停任务需要显式继续。已应用修改的保存断点会先持久化；保存失败后继续只补保存，指纹不匹配则停止，避免重复创建或修改。

正常启动从上次打开的 `.qy` 恢复作品，不用软件设置的更新时间判断或替换作品内容。首次遇到旧版全文本机存储时，会保留其中内容供作者另存为 `.qy`，暂停自动打开最近文件，并在作品集文件建立前保留旧存储；这是过渡保护，不是新的迁移流程。重复启动会唤回已有或最小化的窗口。关窗会等待统一保存队列，真实失败时可以返回应用或明确放弃保存退出。

### 本机服务

Electron 会在回环地址启动本机 Node 服务，默认只允许本机访问：

```text
GET  /api/health
GET  /api/storage
PUT  /api/storage
POST /api/proxy/models
POST /api/proxy/model-limits
POST /api/proxy/test
POST /api/proxy/chat
POST /api/web/search
```

`/api/storage` 管理本机 profile，包含软件设置、作品集路径和按作品隔离的 Agent 工作记录，不保存作品的实时正文与资料副本。服务同时承担 profile 版本校验、模型请求、SSE 流式转发、联网搜索和错误脱敏。API Key 保存在 profile 中，请不要把应用数据目录或导出的配置文件交给他人。

### 桌面 CLI

CLI 使用独立的本机任务服务，每次启动生成随机端口和 bearer 凭据，并拒绝浏览器 Origin。桌面软件必须正在运行，写入目标必须已有 `.qy` 保存路径；CLI 不直接修改作品集文件。

```powershell
node scripts/qy-cli.mjs status --json
node scripts/qy-cli.mjs agent run --current --prompt "补全三位配角的人物动机" --json
node scripts/qy-cli.mjs jobs list --json
node scripts/qy-cli.mjs jobs approve JOB_ID --json
node scripts/qy-cli.mjs save --current --json
```

`--current` 读取一次当前状态并固定绑定作品集与作品 ID，之后切换作品不会改变任务目标；也可以显式使用 `--portfolio` / `--project`，两种方式不能混用。CLI 提供检查、上下文检索、Agent、计划提交、任务管理和保存入口，不能脱离桌面窗口完成全部编辑操作。完整用法和恢复规则见[控制台与 CLI](docs/cli-console.md)。

### 外部 AI 客户端与 MCP

在 **设置 → MCP 连接** 中启用并“保存并应用”，复制对应客户端配置。stdio 适配器自动读取本机认证设置；HTTP 配置中的 `<QY_MCP_TOKEN>` 需要通过“复制认证令牌”取得真实值后替换。

MCP 提供 13 个工具与 3 个只读资源，和桌面 Agent / CLI 共用任务服务。写入先读取 `qy_status`，显式绑定已有保存路径的作品集与作品 ID；MCP 不暴露批准工具，计划由作者在桌面控制台确认。启用、端口和稳定令牌保存在独立的 `mcp-settings.json`，不进入 `.qy` 或 profile。连接步骤、客户端配置、能力和实际验证范围见[MCP 接入](docs/mcp.md)。

构建和完整自动回归通过，最新数字见[路线验收记录](docs/product-roadmap.md#11-验证矩阵)。独立桌面测试已实际完成 MCP 连接表单启用、HTTP / stdio 读取、提交计划、桌面确认、检查点及 `.qy` 保存、锁定拦截，以及备份恢复、外部文件冲突和 MCP 主题状态灯。测试使用合成作品、独立用户数据目录和协议客户端，不调用真实模型 API，也不代表 Codex、Claude Code、DSH、Zcode 已逐一安装登录验证。

## 已知边界

- Agent 会严格遵守锁定字段和操作协议，但创作质量仍需要作者校对；模型的自然语言回复不等于已经写入作品。
- 关键词检索是确定性检索，不是向量搜索。默认只把命中资料、启用规则和确认状态送入模型，不会把所有条目一次性塞入上下文。
- token 统计优先使用服务端 usage；服务端没有返回时，界面只显示本地估算，不伪造缓存命中或精确窗口占用。
- 网络热梗功能依赖搜索引擎和上游网络可访问；搜索不到内容时不会创建空条目。
- API Key 当前保存在本机应用数据中。使用共享电脑前请清理应用数据，并不要把该目录提交到 Git。
- 浏览器页面保留用于开发和兼容调试；作品文件、单实例唤回、窗口控制和本机文件能力等完整体验以 Electron 桌面端为准。
- 控制台任务依赖打开的桌面编辑器。退出软件会暂停任务、处理最后保存并关闭终端，不会继续在后台调用模型；重启后需要显式恢复。
- MCP 已验证本机 HTTP 和真实 stdio 协议接入，未逐一完成 Codex、Claude Code、DSH、Zcode 的安装登录验收；配置模板不代表全客户端实际验收。
