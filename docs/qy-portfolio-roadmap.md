# `.qy` 作品集文件路线

日期：2026-10-06  
状态：前 5 步已完成，包括统一保存、备份恢复及外部文件冲突处理，并通过构建、自动回归与隔离桌面验收；Agent 作品边界和全功能桌面回归仍分项推进。

## 0. 目标重新定义

`.qy` 不是“一部作品的保存文件”，而是一个**作品集文件**。一个 `.qy` 文件可以同时保存多部小说，用户在软件左侧切换作品时，只是在切换同一个作品集里的项目。

作品集文件需要满足：

- 一个文件可以包含多个作品；
- 当前加载的 `.qy` 是这些作品实时内容的唯一持久化位置；
- 每个作品拥有独立的章节、分卷、世界书、角色卡、道具卡、技能卡、大纲、世界引擎、自定义模块、网络热梗和上下文编排；
- 文风规则作为作品集级别的创作内容保存，跨作品继续使用；
- API 预设、API Key、模型列表、主题颜色、自动保存间隔、备份数量、窗口位置等软件设置不写入 `.qy`；
- 当前作品切换只改变编辑上下文，不改变 `.qy` 文件路径；
- 新建作品只在当前作品集内新增项目，不能覆盖当前作品；
- 新建作品集建立新的内存工作区，首次保存时选择新的 `.qy` 文件；
- 打开 `.qy` 的语义是打开一个作品集，而不是替换当前作品的内容。

## 1. 目标数据结构

当前桌面读写格式使用 `version: 2`：

```json
{
  "format": "qy",
  "version": 2,
  "kind": "portfolio",
  "portfolio": {
    "id": "portfolio-uuid",
    "title": "我的作品集",
    "createdAt": 0,
    "updatedAt": 0,
    "activeProjectId": "project-uuid"
  },
  "sharedContent": {
    "styleRules": [],
    "styleGroups": []
  },
  "projects": [
    {
      "id": "project-uuid",
      "title": "作品名称",
      "createdAt": 0,
      "updatedAt": 0,
      "content": {
        "schemaVersion": 10,
        "volumes": [],
        "chapters": [],
        "world": [],
        "characters": [],
        "items": [],
        "skills": [],
        "outline": [],
        "worldEngine": {},
        "customModules": { "schemas": [], "entries": [] },
        "memes": { "entries": [], "updatedAt": 0 },
        "contextBlocks": [],
        "contextGroups": [],
        "resourceGroups": {
          "world": [],
          "characters": [],
          "items": [],
          "skills": []
        }
      }
    }
  ]
}
```

### 文件边界

写入 `.qy`：

- 作品集元数据；
- 所有作品及其全部可填写内容；
- 作品集级文风规则；
- 当前作品 ID；
- 作品集内的折叠栏、排序和上下文编排。

不写入 `.qy`：

- API 预设、API Key、代理密码和模型列表；
- 主题颜色、夜间模式、自动保存间隔和备份数量；
- 窗口大小、窗口位置和桌面运行状态；
- 本机服务地址、缓存和临时文件；
- Agent 对话归档、活动日志和撤销快照，除非后续单独设计“工作记录导出”。
- 控制台任务、步骤事件、保存检查点、CLI 连接凭据和终端会话。

软件设置与 Agent 对话、归档、活动日志、修改历史和撤销快照只保存在本机 profile。这些工作记录使用 `portfolioId:projectId` 隔离；profile 可以保存当前作品集的路径和界面选择，但不能保存或替代作品实时内容。共享文风保存到 `sharedContent`，不进入软件设置。

控制台任务记录另存于本机 `console-jobs.json`，不属于 profile；它最多保存 200 个任务和每任务 200 个事件。任务绑定明确的作品集与作品 ID，其检查点用于防止重复应用修改，不能替代 `.qy` 恢复当前作品内容。CLI 连接文件和运行中的终端也不随作品集迁移。

验证情况：

- 已新增 Electron v2 文件边界测试；
- 已运行全套构建和测试；
- 两部作品、空作品集、损坏文件、重复作品 ID和旧版 v1 都有明确处理。

### 第四步：统一保存和自动保存【已完成】

作品内容不再在本机状态文件与 `.qy` 之间保留两份实时副本。当前 `.qy` 是唯一保存目标，本机 profile 只负责软件配置和工作记录。

- `.qy` 路径只由当前作品集持有；
- 正文保存、文件保存、自动保存、保存保护和关窗刷盘进入同一个串行队列；
- 自动保存、手动保存、另存为不能并发写同一个临时文件；
- 新建、打开、切换、关闭前统一检查脏状态；
- `待自动保存`、`保存失败`、`保存冲突`、`文件冲突`都视为未完成保存；
- 自动保存失败必须保留脏状态并允许重试；
- 关闭窗口必须等待作品集文件写入完成；
- 只有当前 `.qy` 写入完成才能确认作品已保存；
- 无路径时自动保存不弹框，作品保持脏状态；显式保存要求选择文件；
- 首次文件选择取消时返回应用，不弹保存失败提示。

完成情况：

- 新建作品集、打开作品集、打开最近作品集、切换作品和删除作品都会经过统一的保存保护；
- 保存保护提供“保存并继续 / 放弃修改 / 取消”；
- 渲染层和 Electron 层都按同一路径串行化作品集写入；
- 自动保存失败会保留脏状态，并在下一次自动保存或手动保存时重试；
- 关闭窗口会等待统一保存队列，选择取消可继续编辑并重新尝试；
- profile 不再保存作品正文和资料的实时副本，工作记录按 `portfolioId:projectId` 隔离；
- 聊天快照同步是幂等操作，相同消息和活动不会触发新的未保存状态；
- 备份数量为 `0` 时会清理该作品集的备份池，不会回退成默认的 10 个；
- 同名 `.qy` 在不同目录下使用不同的备份池；
- 正常启动从 `.qy` 恢复作品，不使用 profile 更新时间比较作品全文。
- 桌面 Agent 和 CLI 任务的正式修改及保存复用同一 `.qy` 队列；CLI 不直接改文件。

过渡保护：

- 首次发现旧版全文本机存储时保留其中作品内容，暂停自动打开最近文件；
- 建立 `.qy` 之前保留旧存储，不先转换成只含配置的 profile；
- 不新增复杂迁移，也不把这项保护作为 v1 `.qy` 兼容入口。

该阶段验收时构建及 347 项自动测试通过，其中 20 项覆盖 App 的真实保存接线、取消、关窗、旧存储保护和恢复基线。独立桌面测试窗口已成功读取 `.qy` 中的两部作品；本轮新增验收见第五步，完整桌面交互回归未标记完成。

### 第五步：作品集级备份和恢复【已完成】

备份对象从“单作品文件”改成“整个作品集文件”。

- 备份目录以作品集文件的稳定 ID 或完整路径区分；
- 不同目录下同名 `.qy` 不共用备份池；
- 备份数量为 0 时真正表示不保留备份；
- 保存前生成轮转备份；
- 设置中显示备份目录并提供“打开备份文件夹”；
- 可以查看备份时间、作品集名称和文件大小；
- 支持恢复某个备份到新文件，避免直接覆盖当前作品集。

完成情况：

- 设置 → 作品文件显示当前 `.qy`、实际保存 / 备份目录及打开目录按钮；
- 列表按时间排列，显示名称、时间、大小和作品数量；损坏备份保留错误说明并禁用恢复；
- 恢复复用统一写入层，以创建新文件的方式发布，拒绝原文件、备份目录或已存在的目的文件；
- 新文件重建作品集及各作品 ID，章节、资源和内部关联 ID 保持不变；不带走旧身份的本机对话与修改历史；

- 打开文件记录原始字节的 SHA-256，保存前及发布前再次检查；外部修改、删除或新建目的文件时拒绝覆盖；
- 文件冲突提供“另存为 / 重新加载 / 取消”，暂停自动写入，取消保留未保存编辑；
- 重新加载先验证文件与当前目标，异步读取期间新增编辑时停止替换；
- 另存为期间继续编辑会追写新副本；副本已发布而后续文件 / profile 保存失败时，不保留已经解决的旧冲突。

验证：构建、最新自动回归通过；隔离 Electron 使用合成双作品及共享文风完成目录、损坏备份、恢复身份与内容、打开保护、冲突三个选择和发布期间继续编辑，记录 `success: true`。原生选择框与目录打开按 fixture 路径替代，不使用用户作品或模型 API。完整测试数字见[产品强化路线](product-roadmap.md#11-验证矩阵)。

这一步提供版本冲突检测，不提供跨进程文件锁或自动合并。

### 第六步：Agent 与作品集边界【部分完成：控制台目标守卫】

Agent 默认只操作当前作品，不允许因为模型生成了另一个作品名就跨作品写入。

- Agent 请求中明确当前作品 ID 和作品集 ID；
- 创建、更新、删除操作都带目标作品 ID；
- 计划预览显示“作品集 / 作品 / 条目”三级目标路径；
- Agent 如需创建新作品，必须使用独立的 `create_project` 操作并经过确认；
- Agent 不能把一个作品的世界书、角色或章节写进另一个作品；
- 上下文编排只读取当前作品，文风规则读取作品集共享内容；
- Agent 对话、归档和撤销历史只属于本机 profile，按 `portfolioId:projectId` 隔离；工作记录导出另行设计。

本轮已完成：

- 桌面任务与 CLI 显式绑定作品集 / 作品及可选章节，执行前检查当前目标，目标不符不写入；
- `--current` 只读取一次已保存的桌面目标，不追随之后切换；未完成读取或没有 `.qy` 路径拒绝执行；
- CLI 计划经现有 Agent 校验、审批、字段锁与撤销记录处理，再交统一 `.qy` 保存；
- 原子修改后先持久化已应用检查点；保存失败继续只补保存，指纹不符时停止，不重新创建章节或条目；
- 退出暂停任务，重启需显式恢复已有计划或保存断点，不在后台继续推演。

独立 `create_project` 操作、完整三级目标预览和工作记录导出仍待后续实现，不因任务目标守卫完成而整体勾选此步骤。命令和保存边界见[控制台与 CLI](cli-console.md)。

### 第七步：界面反馈和迁移检查

- 文件错误要指出是作品集结构错误、某个作品错误，还是某个条目错误；

## 3. 测试顺序

每完成一步都运行：

```bash
npm run build
npm test
```

另外按下面顺序做桌面手测：

1. 新建作品集，确认自动出现一个空白作品；
2. 在同一作品集中新建第二部作品；
3. 在两部作品中分别写入不同章节和角色；
4. 切换作品，确认内容、上下文和 Agent 目标完全隔离；
5. 保存并关闭，再重新打开作品集；
6. 另存为第二个作品集，确认两个文件互不影响；
7. 自动保存开启时新建、切换、删除作品；
8. 模拟保存失败、关闭窗口和重复启动；
9. 打开损坏文件、空文件和旧版本文件；
10. 确认 API 设置和主题设置没有写进 `.qy`。
11. 查看当前作品集备份，恢复到新路径，检查原文件不变、身份重建且内部关联完整；
12. 外部修改当前文件，分别取消、另存为和重新加载；另存期间继续编辑、后续失败仍可保存。

## 4. 暂不做的内容

以下内容先不放进第一轮作品集改造：

- 云端同步和多人协作；
- 自动合并两个作品集；
- Agent 对话和撤销历史的跨设备迁移；
- 作品级别与作品集级别文风规则的复杂继承；
- 二进制图片的缩略图生成、跨设备打包和增量清理；当前已完成角色图片的 `<作品集.qy>.assets` 内容寻址侧车存储，`.qy` 仅保留图片引用；
- 后台自动合并、冲突解决和实时协同编辑。

后续根据实际使用中的文件大小、保存速度和作品数量，再决定是否增加缩略图、孤儿附件清理或单文件打包。
