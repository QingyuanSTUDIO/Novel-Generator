这份文档记录当前软件已经暴露出的数据风险、反直觉操作和后续强化方向。它包含 `.qy` 作品集改造，但不只处理 `.qy`。每完成一个阶段，都先验证、再进入下一阶段，避免多个基础问题同时变化。

## 0. 优先级和实施原则

### 优先级

- **P0：数据安全和结果正确性**。可能覆盖作品、丢失修改、错误写入或发送错误资料的问题，必须优先处理。
- **P1：核心流程的可解释性和稳定性**。不会立刻丢数据，但会让 Agent、检索、世界引擎或保存行为与用户理解不一致。
- **P2：交互、视觉和工程维护**。在核心数据边界稳定后处理。

### 实施原则

1. 先固定数据契约，再改界面。
2. 新建、打开、切换、删除和保存都走统一的状态守卫。
3. Agent 只能提出计划，桌面端负责校验、确认和执行。
4. 所有发送给模型的资料都要能解释来源、是否启用和为什么被裁剪。
5. 所有可能覆盖数据的动作都要留下可恢复路径。
6. 每个阶段都运行构建、自动测试和桌面手测，不跨阶段堆改动。

## 1. P0：作品集文件和保存安全

### 1.1 把 `.qy` 定义为作品集文件【已完成：数据契约】

`.qy` 不再代表一部作品，而是一个包含多部作品的作品集文件。一个文件内保存：

- 作品集元数据和作品列表；
- 每个作品的章节、分卷、正文、世界书、角色卡、道具卡、技能卡、大纲、世界引擎、自定义模块、网络热梗和上下文编排；
- 作品集级文风规则；
- 当前作品 ID、排序和折叠栏状态。

已完成内容：

- 新增 `PortfolioDocument`、`PortfolioProject`、`PortfolioProjectContent` 和 `PortfolioSharedContent` 类型；
- 新增 `version: 2` / `kind: "portfolio"` 严格校验；
- 新增双作品、共享文风、活动作品 ID、重复 ID 和设置泄漏测试；
- 旧版 `QyDocument` API 仅保留历史测试边界，桌面读写使用 v2 作品集。

不保存 API 预设、API Key、代理密码、模型列表、主题颜色、自动保存间隔、备份数量、窗口位置和本机服务状态。

详细字段和实施顺序见 [`.qy` 作品集文件路线](qy-portfolio-roadmap.md)。

### 1.2 修复文件路径串写

`currentQyPath` 表示当前加载的作品集文件，当前规则：

- `.qy` 路径只属于作品集；
- 当前作品只由 `currentProjectId` 表示；
- 切换作品永远不改变 `.qy` 路径；
- 新建作品只向当前作品集追加项目；
- 新建作品集清除旧路径，首次保存时选择新的 `.qy`；
- 打开 `.qy` 是打开作品集，不是用一个作品覆盖当前作品。

### 1.3 统一未保存保护【已完成】

以下操作必须使用同一个确认流程：

- 新建作品集；
- 打开作品集；
- 打开最近作品集；
- 切换作品；
- 删除作品；
- 关闭窗口。

`未保存`、`待自动保存`、`保存失败`、`保存冲突`、`文件冲突`都视为存在未完成修改。作品操作提供“保存并继续、放弃修改、取消”；“保存并继续”和关闭刷盘都走作品集统一队列。未建立 `.qy` 时显式选择文件；作者取消选择则留在应用，真实失败时才提供返回应用或放弃保存并退出。

### 1.4 统一作品内容保存【已完成】

作品实时内容的唯一持久化位置是当前加载的 `.qy`。以下入口共用同一保存链路：

- 正文区保存；
- 文件菜单保存和另存为；
- 自动保存；
- 保存保护中的“保存并继续”；
- 关窗刷盘。

保存内容包括当前作品集内的全部作品及共享文风；只有 `.qy` 写入完成才能确认作品已保存。没有文件路径时，自动保存不弹框，也不会清掉作品脏状态；显式保存打开文件选择框，首次选择取消不报保存失败。

API、主题等设置与 Agent 对话、归档和撤销历史只进入本机 profile。工作记录按 `portfolioId:projectId` 隔离，不能代替作品集文件恢复当前正文。文风属于作品集创作内容，不属于软件设置。

首次遇到旧版全文本机存储时，保留其内容，暂停自动打开最近文件，并在建立 `.qy` 前保留旧存储，不先转换成只含设置的 profile。此处仅处理过渡数据安全，不增加复杂迁移。

该阶段验收时构建及 347 项自动测试通过，其中 20 项运行 App 的真实保存接线。独立桌面测试窗口可从 `.qy` 恢复两部作品；本轮新增备份与冲突验收见 1.6，全功能桌面回归仍保留为后续验收项。

### 1.5 串行化作品集写入【已完成】

自动保存、手动保存、另存为和关闭刷盘必须进入同一个写入队列：

- 同一个 `.qy` 不允许并发写临时文件；
- 关闭窗口必须等待正在进行的 `.qy` 写入；
- 自动保存失败后保留脏状态并允许重试；
- 临时文件使用唯一名称，并在写入失败后清理；
- 保存时记录 generation，避免旧写入覆盖新写入。
- 聊天快照同步保持幂等，相同消息和活动记录不会让保存过程再次产生脏状态。

### 1.7 控制本机服务的安全边界【已完成：任务与 profile 鉴权】

## 2. P0：Agent 结构正确性和写入安全

### 2.1 标准卡必须返回完整结构【已完成】

世界书、角色、道具、技能的 `create_resource` 不允许只返回摘要。目标：

- `includeAllFields` 和完整字段结构必须通过校验；
- 缺字段时拒绝执行或明确补全默认值；
- 计划中显示缺失字段；
- “创建成功”只代表完整结构已经写入；
- 道具、角色、技能和世界书分别使用各自模板，不能混用。

### 2.2 结构边界不能串栏【已完成】

标准资源和自定义模块使用不同操作协议：

- 标准卡只能创建标准字段；
- 新结构必须先创建自定义模块 schema；
- 自定义模块条目不能偷偷写入世界书；
- Agent 计划显示目标类型和目标路径；
- 结构编辑模式只修改整类模板的强化提示词，不把提示词当成条目内容。
- 标准卡更新同样拒绝新增模板外字段；大纲元数据字段纳入统一协议校验；同一计划内自定义 schema → entry 只允许按稳定 schema ID 关联。

### 2.3 更新必须区分创建和修改【已完成】

- 新建 ID 永远由桌面端生成；
- 更新必须命中现有 ID；
- 模型生成的未知 `targetId` 不能自动创建；
- 更新前校验目标类型、所属作品和锁定状态；
- 允许显式清空名称、摘要和字段，而不是把空字符串当作“没有提供”。

### 2.4 计划显示字段级差异【已完成：字段差异与逐项审批】

Agent 待确认计划需要显示：

- 原值 → 新值；
- 新建、修改、删除和移动分别标记；
- 清空字段醒目标记；
- 锁定字段被跳过的原因；
- 跨折叠栏移动的来源和目标；
- 预计影响的作品、条目和字段数量。

当前计划已显示结构化字段差异，并保留旧计划文本回退；执行前可以查看完整 JSON。Agent 和桌面控制台都支持逐项勾选、全选 / 取消全选和至少一项校验。若所选操作依赖同一计划内创建的自定义模块、分卷或折叠栏，依赖会自动一并勾选；取消依赖时会同步取消依赖它的后续操作。

### 2.5 锁、撤销和回滚一致【已完成：Agent 与控制台路径】

- 字段小锁禁止 Agent 修改对应字段；
- 条目大锁一键同步所有字段锁；
- 部分锁定显示中间状态；
- 执行失败时恢复 Store、选中条目、折叠栏选择和当前页面；
- Agent 撤销显示可撤销条件；
- 手动编辑也逐步加入统一历史记录，而不是只依赖 Agent 快照；这一项仍属于后续历史系统收口。
- Agent / 控制台执行失败会恢复内容、页面和选择状态；应用断点保存失败保留可重试状态与撤销记录；撤销会校验变更后指纹，发现后续手动修改时拒绝覆盖。

### 2.6 Agent 工作边界明确【已完成：当前作品强绑定】

默认 Agent 只操作当前作品：

- 请求中携带作品集 ID 和当前作品 ID；
- 计划中显示三级目标路径；
- 创建新作品必须使用独立操作并单独确认；
- Agent 不能因为模型输出了另一个作品名就跨作品写入；
- Agent 创建、删除、移动折叠栏必须进入计划确认。
- 控制台、MCP 与桌面 Agent 计划均固定作品集 ID、作品 ID，并在计划审阅中显示目标路径；异步执行、恢复和保存断点都会再次校验目标与内容指纹。

### 2.7 资料内容与指令隔离【已完成】

世界书、卡片、自定义模块、网络热梗和联网搜索结果都是资料，不是系统指令。发送给模型时：

- 使用明确的 DATA 分隔块；
- 在系统协议中声明资料字段不能改变操作权限；
- 字段中的“忽略前文”“调用工具”等内容只能作为文本资料；
- 外部搜索结果保留来源和不可信标记；
- Agent 操作协议只从模型的结构化操作区读取。

## 3. P1：检索、上下文和 Token 可解释性

### 3.1 显示本次实际读取范围【已完成：首轮】

每次正文生成、Agent 请求和世界引擎推演都提供上下文预览：

- 实际读取的世界书、角色、道具、技能、大纲、自定义模块和热梗；
- 每项的触发来源；
- 未读取资料及原因；
- 常驻、关键词、强制出场和递归深度；
- 每一类占用的 Token；
- 被预算裁剪的资料。

正文、Agent 和世界引擎都已接入可折叠的实际上下文预览，显示本次发送的消息分段、资料命中、递归层级、触发来源、编排关闭 / 禁用 / 条数预算 / Token 预算导致的跳过项，以及本地估算和回复预留。

### 3.2 禁用资料不能被隐式绕过

强制出场角色也必须检查资源的启用状态。若产品决定允许覆盖禁用状态，界面要明确显示“本次强制读取”，不能静默发送。

### 3.3 常驻资料也要受预算控制【已完成：检索层与调用侧预算已接入】

检索层已支持常驻条目遵守总 `maxResults` 和 `maxTokens` 预算，并返回每条被省略资料及 `disabled`、`max-results`、`max-tokens` 原因。正文、Agent 和世界引擎都从所选 API 预设计算可用输入预算，发送前由统一聊天客户端再次按上下文窗口、回复预留和安全余量校验；界面把本地估算和接口返回 usage 分开显示。

- 数量上限；
- Token 上限；
- 稳定优先级；
- 裁剪记录；
- 上下文预览中的实际命中数量。

### 3.4 只保留一种主表示，避免重复注入【已完成：Agent 检索索引已去重】

当前同一资料在 Agent 请求中采用有序 DATA 文本作为唯一完整内容表示，结构化检索索引只保留身份、命中来源、注入顺序和锁定元数据：

- 每类资料选择一种主表示；
- 另一种只保留 ID、摘要或 Debug 预览；
- 世界引擎、自定义模块和检索结果不重复发送；
- Agent 页面显示实际发送包，而不是仅显示界面上的命中数量；外部控制台仍可读取完整的安全投影。

### 3.5 自定义模块和网络热梗按需读取

不再无条件塞入前 24 条。使用以下任一条件：

- 当前关键词命中；
- 上下文编排启用；
- 用户明确要求读取；
- 专门的“本次注入”开关。

### 3.6 Token 计算必须跟随内容变化【已完成：上下文编排估算】

- 内容、结构、排序、启用状态和折叠状态变化时重新计算；
- 全部子项关闭时不再回退计算整个资料块的旧 Token；
- 本地估算与服务端 usage 分开显示；
- 服务端未返回缓存命中或上下文窗口时保持“未知”；
- 发送前显示输入、输出和安全余量。

### 3.7 上下文编排的交互语义

- 如果大类表示资料类型，禁止跨大类拖动；
- 如果大类表示提示词位置，文案改成“提示词归属”，允许跨类移动；
