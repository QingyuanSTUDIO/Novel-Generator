# 叙事工坊：当前产品与技术框架

日期：2026-10-06。状态：已落地的桌面端实现说明与数据契约。

本文档描述仓库当前已经实现的产品行为、数据边界和技术结构。它不是早期原型提案，也不承诺当前代码中不存在的数据库、云同步、多人协作或后台自主运行能力。界面和数据结构继续演进时，应先更新本文件，再更新 Agent 的 JSON 契约和测试。

## 1. 产品定位与运行边界

叙事工坊是一个本地优先的长篇小说创作工作台。作者以章节为中心写作，同时维护世界书、角色卡、道具卡、技能卡、大纲、世界引擎、文风规则、自定义模块和网络热梗。AI 负责生成候选内容、提出结构化修改计划和推演建议；作者决定是否采纳。

产品运行在 Electron 独立窗口中。Vue 3 + TypeScript + Vite 负责渲染，Electron 主进程负责无边框窗口、单实例、作品集文件和生命周期，本机 Node HTTP 服务负责应用 profile 持久化、模型代理和联网搜索。浏览器页面仍能作为开发 / 兼容预览运行，但完整产品边界以桌面端为准。

当前明确不包含：账号体系、云端同步、多人协作、SQLite / ORM 数据库、向量数据库、自动连续写完整本书、未确认状态自动写回作品，以及没有来源的隐式 Agent 操作。

## 2. 信息架构与布局

主界面使用单页导航，不使用 Vue Router。左侧大功能栏按以下分组排列：

1. **开始写作**：章节写作。
2. **创作空间**：世界书、角色卡、道具卡、技能卡、自定义模块、网络热梗。
3. **全局把握**：故事大纲、世界引擎。
4. **AI 功能**：AI Agent、控制台。
5. **全局功能**：文风规则。
6. **Debug**：上下文编排、JSON 结构查看器。

API 预设和软件设置从右上角的设置按钮打开，不占用主导航。桌面端使用自定义无边框标题栏，包含作品文件菜单、MCP 连接状态、保存状态、夜间 / 白天切换、设置、最小化、最大化和关闭。MCP 状态位于“已保存”左侧，字体读取 `--theme-font`，未连接 / 已连接灯分别读取 `--theme-danger` / `--theme-success`。

设置的独立竖栏还提供 MCP 页面，管理本机外部 AI 客户端连接的启用、端口、状态、认证令牌和客户端配置复制；MCP 不占用创作栏目。

写作页采用“章节目录 + 正文编辑区 + 右侧任务 / 资料区”的布局，底部控制台可折叠并拖动调整高度。资料卡页采用“左侧条目 / 折叠栏 + 右侧详情编辑”的布局；左右栏分别滚动，避免操作一侧时另一侧跳动。Agent 悬浮球可自由拖动，弹出的 Agent 窗口跟随悬浮球位置。

独立控制台位于 AI 功能下，分任务视图和真实终端视图。任务视图显示计划、进度、结果和保存状态；终端运行本机 PowerShell、cmd 或已安装的 Codex 命令。任务步骤事件、终端命令输出和 Electron 启动诊断属于不同记录，不能把任务日志当作完整启动 stderr。

## 3. 作品与全局数据边界

### 3.1 Store：作品内容

当前作品在内存中使用 `Store` 编辑；文件内保存为 `projects[].content`。`Store` 同时含有共享文风和软件配置的编辑视图，序列化时按下面的边界拆分：

| 数据 | 用途 |
| --- | --- |
| `volumes` / `chapters` | 分卷、章节、正文、状态、字数、任务目标和出场人物 |
| `world` | 世界书条目 |
| `characters` | 角色卡和角色持有关系、图片 |
| `items` | 道具卡 |
| `skills` | 技能卡 |
| `outline` | 全书、卷、章节范围和场景组成的嵌套大纲 |
| `style` | 当前作品集的共享文风编辑视图，写入 `.qy` 的 `sharedContent.styleRules` |
| `worldEngine` | 世界时间、后台角色状态、关系、事件、时间线、笔记、提案和日志 |
| `customModules` | 自定义模块 schema 与具体条目 |
| `memes` | 网络热梗专表 |
| `contextGroups` / `contextBlocks` | 两级提示词编排布局和兼容投影 |
| `resourceGroups` | 世界书、角色、道具、技能的作品级折叠栏；文风分组写入 `sharedContent.styleGroups` |
| `providers` / `modelOptions` | API 预设和模型列表；属于应用级配置，`.qy` 不导出 |

每个标准资料条目使用稳定 `id`、显示名称、摘要、字段字典、检索设置、注入排序、锁定字段和校对元数据。字段字典保留中文字段名作为提示词契约的可读键名。

### 3.2 全局设置

以下软件设置只保存在本机 profile：API 预设、模型列表、自动保存间隔、Agent 修改历史上限、`.qy` 备份数量、主题颜色和格式化缩进。作品切换、新建或打开其他 `.qy` 不应覆盖这些设置。

文风规则属于作品集级创作内容，随 `.qy` 的 `sharedContent` 保存，同一作品集内共享；它不是软件设置。

### 3.3 本机工作记录

Agent 对话、归档、活动日志、修改历史和撤销快照只保存在本机 profile，使用 `portfolioId:projectId` 隔离并随目标作品恢复，不写入 `.qy`。迁移作品集不会自动带走这些工作记录。撤销快照可以包含历史文本，但不作为当前作品内容的实时保存副本。

控制台任务及步骤事件另存于用户数据目录的 `console-jobs.json`，明确绑定作品集、作品及可选章节 ID，不进入 profile 或 `.qy`。它最多保留 200 个任务、每任务最近 200 个事件；执行中、暂停、待确认及已应用但保存失败的检查点不会为了腾出空间而被裁剪。

MCP 连接配置另存于 `userData/mcp-settings.json`，包含启用开关、固定端口及稳定令牌，不进入 profile 或 `.qy`。首次默认关闭，端口 `43127`；重启沿用已保存配置，轮换令牌是单独显式动作。

## 4. 作品文件、持久化与恢复

一个 `.qy` 保存一个作品集，作品集内包含多个作品。桌面端使用 v2 契约，统一保存、备份恢复界面及外部文件冲突处理已完成，并通过隔离桌面验收。完整改造顺序记录在 [`docs/product-roadmap.md`](product-roadmap.md)，文件结构细节记录在 [`docs/qy-portfolio-roadmap.md`](qy-portfolio-roadmap.md)。

### 4.1 `.qy` 文件

`.qy` 是版本化 JSON 文件，当前格式为：

```json
{
  "format": "qy",
  "version": 2,
  "kind": "portfolio",
  "portfolio": {
    "id": "portfolio-uuid",
    "title": "我的作品集",
    "createdAt": 0,
    "updatedAt": 0,
    "activeProjectId": "project-uuid"
  },
  "sharedContent": { "styleRules": [], "styleGroups": [] },
  "projects": [{
    "id": "project-uuid",
    "title": "作品名称",
    "createdAt": 0,
    "updatedAt": 0,
    "content": {
      "schemaVersion": 10,
      "volumes": [],
      "chapters": [],
      "world": [],
      "characters": [],
      "items": [],
      "skills": [],
      "outline": [],
      "worldEngine": {},
      "customModules": { "schemas": [], "entries": [] },
      "memes": { "entries": [], "updatedAt": 0 },
      "contextBlocks": [],
      "contextGroups": [],
      "resourceGroups": { "world": [], "characters": [], "items": [], "skills": [] }
    }
  }]
}
```

`projects[].content` 保存每个作品的章节、分卷、世界书、角色、道具、技能、大纲、世界引擎、自定义模块、网络热梗和上下文布局；`sharedContent` 保存作品集共享文风与文风折叠栏。文件不含 API Key、API 预设、模型列表、主题、自动保存间隔、备份数量或 Agent 工作记录。打开前严格校验版本、作品结构、重复 ID 和有效的当前作品 ID；v1 单作品文件明确拒绝，不静默补成空作品集。

文件菜单区分新建作品集与新建作品。打开 `.qy` 恢复全部作品和共享文风，作品切换保持相同的文件路径。保存前备份整份作品集，只有成功发布后才裁剪超出数量的旧备份；不同路径的同名文件拥有独立备份池，数量为 `0` 时不保留备份。最近文件最多显示 30 条。

### 4.2 统一作品保存

当前加载的 `.qy` 是作品实时内容的唯一持久化位置。正文保存、文件保存、另存为、自动保存、操作前保存保护和关窗刷盘共用串行队列，写入作品集内全部作品及共享文风。写入使用独立临时文件并等待原子替换完成；保存期间发生的新修改继续保留脏状态，旧快照不能清除新修改。

自动保存由设置中的 0 / 5 / 10 / 30 / 60 / 300 秒间隔控制。没有 `.qy` 路径时自动保存不弹框，作品内容仍未保存；显式保存、“保存并继续”和关窗保存要求选择文件。取消首次选择会留在应用，不弹保存失败提示。真实失败保留脏状态并允许重试；关窗失败提供“返回应用”或“放弃保存并退出”，成功则等待队列完成后关闭。

生成作品或工作记录快照时，聊天同步仅在消息和活动内容真正变化时更新响应式状态；同一份聊天不会因保存快照产生新修改。

### 4.3 本机 profile 服务

Electron 在 `userData` 下启动绑定 `127.0.0.1` 的 Node 服务。`/api/storage` 保存软件配置、当前作品集路径、界面选择和按作品隔离的 Agent 工作记录，不保存作品实时内容。profile 文件使用临时文件写入再原子替换；`PUT /api/storage` 携带 `expectedUpdatedAt`，版本不一致时暂停 profile 覆盖。

正常启动从上次打开的 `.qy` 恢复作品，profile 更新时间只属于软件设置和工作记录，不与作品全文进行时间比较。首次遇到旧版全文本机存储时保留其作品内容，暂停自动打开最近文件，并在建立 `.qy` 前保留旧存储；这只是过渡数据保护，不引入新的复杂迁移。Electron 使用单实例锁，重复启动会恢复、显示并聚焦已有窗口，包括最小化窗口。

### 4.4 备份界面与恢复

设置 → 作品文件显示当前路径、`userData/保存` 与 `userData/备份` 的实际目录，提供打开目录、轮转数量和刷新入口。列表只展示当前完整路径对应的备份，含时间、名称、作品数量、大小及校验结果；损坏备份可见但不能恢复。

恢复通过当前窗口的主 frame IPC，主进程验证备份归属、真实文件和目录，拒绝符号链接 / junction 及备份读取期间替换。恢复严格解析 v2，重新生成作品集及作品 ID，重映射活动作品，内部章节和条目关联 ID 不变。复用统一写入层的 `createOnly` 发布，拒绝覆盖原文件、备份目录或任何已有目的文件。

成功后只生成副本并添加最近文件；当前编辑保留。作者明确选择打开副本时走原有保存保护。本机对话和历史按新身份隔离，不从原作品直接继承。

### 4.5 外部文件冲突

打开文件时记录原始字节的 SHA-256。保存请求携带期望版本，写入层在准备和发布前检查磁盘；文件被修改、删除或原本不存在的目的文件被创建时返回 `QY_FILE_CONFLICT`，不覆盖目标。失败清理新临时文件及未发布备份，不裁剪之前的备份。

“文件冲突”独立于 profile 的“保存冲突”。文件冲突暂停自动写入，提供另存为、重新加载磁盘版本和取消；取消保留编辑。重新加载需要作者明确放弃未保存内容，异步排队 / 读取期间新增编辑或切换目标时拒绝替换。关闭遇到文件冲突返回编辑器。

另存为成功后立即解除原文件冲突，继续捕获并写入同一新副本中的新增编辑。旧保存回信通过请求 epoch、来源文件及作品集身份验证，不能清掉新冲突或改写另一目标的路径。副本已发布而追写 / profile 保存失败时保留新路径、已确认基线和未保存状态，允许普通保存重试。

这些检查不是跨进程文件锁，不提供外部修改自动合并。

## 5. 标准资料模型

### 5.1 世界书、角色、道具和技能

四类标准资料都支持：名称、摘要 / 内容、触发策略、触发键、递归选项、注入排序、分组和锁定状态。触发策略是 `关键词` 或 `常驻`，默认是关键词；角色、道具和技能没有手动触发键时使用自身名称作为默认触发词。递归和进一步递归默认关闭。

角色卡额外包含角色身份（主角 / 配角 / 路人）、性别、种族、性格、外貌、人物信息、动态状态、持有道具和持有技能。持有物品和技能以标签显示，可以通过加号关联现有卡片，并点击标签查看详情。角色图片独立于 AI 上下文，支持多图、裁切、9:16 竖向封面、设为封面和删除。

技能卡的性质只有主动 / 被动两项；技能效果使用可伸缩输入。道具卡保存用途、持有人、位置、限制、正文证据和关联线索等字段。标准卡都支持结构编辑模式：作者可以预览发给 AI 的通用 JSON 结构，并编辑整类卡片的“强化提示词”。强化提示词用于 Agent 创建这类卡片时解释字段含义，不会被当成每个已有条目的独立内容。

### 5.2 文风规则

文风规则是同一作品集内共享的创作约束，切换作品时继续使用并随 `.qy` 保存。规则支持启用开关、折叠栏、拖动排序、规则内容、正例、反例和整体强化提示词。写作模式会把启用的规则作为底层提示词，用于正文、世界书、角色、道具、技能和自定义模块的创作；灵感模式可以不受文风约束，但仍读取世界资料。

### 5.3 大纲

大纲层级为：

```text
全书
└── 卷
    └── 章节范围
        └── 场景
```

父子类型和循环关系在本地校验。卷、章节范围和场景可以折叠，节点包含目标、冲突、关键转折、结尾状态、视角 / 地点和章节范围等字段。世界引擎读取大纲作为剧情目标和因果约束；旧的“伏笔”大栏目不再作为独立数据源。

## 6. 检索与上下文编排

### 6.1 确定性检索

当前检索只使用常驻 / 关键词策略，不使用向量检索或随机触发。检索输入来自当前章节标题、任务目标、正文、出场人物和 Agent 当前需求。结果来自世界书、角色、道具、技能、大纲和文风条目。

检索流程：

1. 先选出常驻条目和直接关键词命中的条目。
2. 根据条目的递归开关，从条目内容和字段中继续匹配其他条目。
3. 使用最大递归深度和结果数量上限，避免一次请求膨胀。
4. 按注入排序、递归深度和原始顺序稳定排序。
5. 将命中条目、命中键、深度和顺序格式化为提示词资料。

所有新建标准卡的递归字段默认关闭。检索不会因为条目被找到就改变条目内容，也不会把模型的推测当作确认事实。

### 6.2 两级上下文布局

上下文编排使用“提示大类 → 大类内资料项”的两级结构。当前大类包括系统约束、世界书、角色卡、道具卡、技能卡、文风规则、自定义模块、世界引擎、大纲 / 本章任务、近期正文和输出要求。大类和条目都可以启用、禁用、折叠和拖动。

布局顺序就是组装提示词时的顺序。自定义模块也属于可编排资料，不再作为隐藏的单独通道。正文、Agent 和世界引擎共用这套布局，但每个调用会根据自身检索结果选择实际条目。

上下文 token 在资料内容或布局发生变化时重新估算，不再只读取初始化时的旧 `tokens` 值。估算值用于本地预算提示；模型实际返回的 usage 单独显示，缺少提供方字段时保持未知。

## 7. AI Agent 协议与安全边界

### 7.1 两种模式

- **写作模式**：所有创作性回复、正文和资料文字都必须遵守启用的文风规则。
- **灵感模式**：可以自由讨论剧情和发散想法，不强制套用文风规则；仍须把检索资料视为事实边界，明确区分推测和确认状态。

两种模式都会读取当前章节、上下文检索包、世界引擎状态、自定义模块契约、网络热梗和最近 Agent 对话历史。聊天历史用于理解前后文，不能替代作品数据。

### 7.2 JSON 操作协议

Agent 必须返回：

```json
{
  "message": "给作者看的简短结果",
  "operations": []
}
```

当前操作包括：

- 搜索网络热梗；
- 创建 / 更新世界书、角色、道具、技能、大纲、世界引擎事件和文风规则；
- 创建章节和分卷，追加章节正文；
- 创建、删除和移动世界书 / 角色 / 道具 / 技能 / 文风折叠栏；
- 创建自定义模块 schema，创建 / 更新 / 删除自定义模块条目。

标准资源创建必须使用完整模板字段；更新只允许写目标条目已有的标准字段，不允许借机创建独立的自定义结构。需要新的结构时必须使用 `create_custom_module`，再用对应的条目操作写入数据。这条边界用于避免模型把一个道具误拆成多个世界书条目。

### 7.3 计划、确认、锁和撤销

Agent 先生成操作计划和可读描述。作者确认后，前端再次校验目标、字段和引用，再执行操作。锁定字段、校对状态锁和整条目大锁会阻止对应修改；整条目解锁时会同步恢复字段锁状态。

每次 Agent 执行的前后快照、摘要和变更列表属于 profile 工作记录，按作品集与作品隔离；产生的正式作品修改通过统一队列保存到 `.qy`。只有最近一笔、且作品之后没有发生冲突修改的操作可以直接撤销。对话、活动日志和修改记录可以在设置中限制保留数量。Agent 不是后台持续自主运行的进程，所有写入都经过当前窗口的本地操作执行器。

### 7.4 任务服务、CLI 和恢复

桌面 Agent 与 CLI 使用同一任务入口，再委托现有 Agent 操作执行器完成结构校验、预览、审批、字段锁和修改记录。任务默认串行执行；待确认计划会阻止后续生成，作者可以批准、暂停、恢复或终止任务。恢复已有预览使用原计划，不重新调用模型生成一份替代计划。

专用任务服务只监听 `127.0.0.1`，每次启动生成随机端口和 bearer 凭据，写入本机 `console-endpoint.json`。请求必须认证，不开放浏览器 CORS，并拒绝带 Origin 的调用。CLI 不直接修改 `.qy`，只向正在运行的桌面端提交检查或任务；写入目标必须已经打开或保存为 `.qy`。

CLI 提供 `status`、`inspect`、`context`、`providers`、`schema`、`agent run`、`plan submit`、`jobs` 和 `save`。写入使用显式作品集 / 作品 ID，或通过 `--current` 读取一次状态并固定绑定这两个 ID；它不追随之后的作品切换，也不能与显式 ID 混用。目标不符、未完成读取或没有保存路径时明确拒绝执行。

应用修改后先持久化 `applied` 和内容指纹检查点，再进入统一作品集保存队列。保存失败时保留检查点；显式继续只校验并补保存，不重复调用生成或应用操作。指纹不匹配时停止恢复。原子修改已开始时，退出流程等待检查点和保存处理，不把部分执行冒充未执行。

退出软件会暂停任务并关闭终端，重启不自动重跑任务。CLI 是当前桌面工作区的有限操作入口，不是独立运行全部编辑功能的 headless 产品。具体命令、连接和恢复规则见[控制台与 CLI](cli-console.md)。

### 7.5 MCP 外部客户端入口

MCP 使用官方 SDK v2 提供固定本机端口的 Streamable HTTP 及真实 stdio 适配，13 个工具与 3 个资源共用上述桌面任务服务。外部客户端可以读取资料、检索、调用内置 Agent，或根据 schema 自行生成 AgentResponse 并通过 `responseJSON` 字符串提交计划；它不直接操作 `.qy`。

写入必须提供明确作品集 / 作品 ID，目标需已打开并保存。MCP 不提供批准工具，计划在桌面控制台由作者确认，再检查锁、目标与内容指纹并调用统一保存。HTTP 每个请求验证 Bearer、拒绝 Origin、限制本机 Host / 端口及 2 MiB 请求；输出安全投影不包含密钥和角色图片。

客户端模板覆盖 Codex TOML、Claude Code `.mcp.json`、DSH Cordis overlay 和 Zcode `mcp.servers`。stdio 配置只带脚本、Node 与独立设置文件路径，适配器每次操作重读端口和令牌；HTTP 通用配置只带令牌占位，需要单独复制。启用和使用细节见[MCP 接入](mcp.md)。

主界面状态按有效 MCP 活动判断，服务启用不等于客户端已连接。认证及 SDK 协议处理成功后建立 90 秒活动租约，超时推送未连接；stdio 适配器使用独立客户端 ID，每 20 秒心跳，退出 / EOF 用认证 DELETE 撤销自身租约。无 ID 的直接 HTTP 合为一个活动组。停用、重启、端口或令牌变化清空租约，过期请求不能复活已撤销连接。

## 8. 世界引擎

世界引擎全面接管旧伏笔功能。它读取大纲、正文、检索到的世界资料和已确认的角色 / 道具 / 技能状态，输出可审阅的世界变化：

- 天下大势、事件链和后果；
- 主角与配角的行动、关系和下一步目标；
- 时间线、工作笔记和线索状态；
- 可以提供给正文与 Agent 的已确认世界状态。

路人角色不会自动进入关系推演。推演时间通过当前、按章、按天、按月和自定义天数推进；自定义时间只表示推进若干天，不使用分钟级自动推进。世界引擎可以选择不同于主线写作的 API。推演结果先进入待确认提案，作者确认 / 拒绝后才更新正式状态。

## 9. 自定义模块与网络热梗

### 9.1 自定义模块

自定义模块是实验性但可持久化的结构编辑器。作者先定义模块类型、描述和字段，再创建具体条目。字段类型包括：

```text
string / text / longText / number / enum / boolean / tags
characterIndex / itemIndex / skillIndex
```

每个字段有 key、标签、描述、默认值、枚举选项、必填状态、锁定状态和强化提示词。引用字段存稳定卡片 ID，界面显示为可点击标签；删除被引用卡片时，完整性清理会移除无效引用。

Agent 可以读取模块 schema、JSON 契约、示例和现有条目，也可以在用户确认后创建 / 更新 / 删除模块条目。标准资源和自定义模块使用不同的操作类型，避免结构串栏。

### 9.2 网络热梗

网络热梗使用独立的 `MemeStore`，字段包括名称、含义、适用场景、例句、来源、日期、关键词、启用、锁定、创建来源和校对状态。Agent 不能把网络热梗写成世界书条目。

收到搜索需求后，Agent 应返回 `search_web_memes` 操作。桌面端会把自然语言拆成若干查询，按选定的 Bing、Google 或 DuckDuckGo 分批搜索，去重后再调用整理流程提炼名称、表达、含义和使用场景，最后写入热梗表。搜索候选和已保存条目可以在热梗页面本地搜索和管理。

## 10. API、模型和本机代理

API 预设由右上角设置面板管理，协议枚举为：

```text
OpenAI Compatible / Anthropic / Google Gemini / 自定义 HTTP
```

默认协议是 OpenAI Compatible。预设可以启用为默认 API；正文、Agent 和世界引擎可分别选择 API。模型列表通过本机服务从当前地址拉取，界面使用下拉栏选择模型；不支持列表的服务可以手动填写模型。

每个预设可配置：

- Base URL、API Key、模型和连接状态；
- 上下文长度、最大输出、历史预算；
- 温度、Top P、频率惩罚、存在惩罚；
- 流式输出和流式 usage 统计；
- 上游 HTTP 代理地址、端口、协议、用户名和密码；
- 输出 token 参数（`max_tokens` 或 `max_completion_tokens`）。

服务端按协议转换请求和流式响应，支持 SSE 增量、取消、空闲超时、错误脱敏和 usage 归一化。Gemini 的模型列表、请求和 usage 使用其原生字段；Anthropic 的不支持参数会在发送前拒绝。服务端未返回上下文窗口或缓存数据时，界面不会伪造精确值。

## 11. 主题、设置与桌面生命周期

主题设置分别保存白天和夜间调色板，每套包含主色 / 背景、次配色、按钮、字体、成功、危险、提醒和信息颜色。界面组件使用主题变量，不应直接写死状态色或标题色。设置还包括自动保存、Agent 历史上限、`.qy` 备份数量、格式化缩进和归档 Agent 对话管理。

Electron 主进程使用单实例锁、启动日志和独立可写的 Chromium session/cache 目录。窗口渲染失败、加载失败、本机服务失败和保存失败都会记录诊断信息；应用不会在本机状态服务不可用时用示例内容覆盖用户作品。

收起控制台不影响仍然打开的软件中的执行。关闭应用或重新加载会暂停任务；取消关闭后，显式提交新任务恢复调度，之前暂停的任务继续保持暂停。软件关闭后不继续后台推演，真实终端会话也不跨重启延续。

## 13. 验证与已知限制

提交前至少运行：

```bash
npm run build
npm test
```

当前测试覆盖 Agent 操作与校验、标准资源结构、上下文预算与布局、章节和段落编辑、写作生成、世界引擎、模型上限、流式聊天、服务端存储和安全边界，以及控制台目标隔离、CLI 一次绑定、取消后的晚返回、审批检查点和保存恢复。

构建及完整自动回归通过，最新数字见[路线验收记录](product-roadmap.md#11-验证矩阵)。MCP 专项覆盖官方协议客户端与真实 stdio、认证与输出过滤、固定目标 / 幂等任务、端口及令牌变化、设置持久化、审批边界、心跳 / 断开 / 空闲失活和主题状态灯。文件专项覆盖目录 IPC、恢复身份与内容、目的文件保护、版本冲突、旧回信及保存期间继续编辑。隔离 Electron 已完成备份与冲突界面、MCP 状态与主题的实际交互；此前 MCP 集成已完成 HTTP / stdio、桌面审批、检查点、`.qy` 保存和锁拦截。未使用用户作品或模型 API，也未逐一完成外部客户端安装登录；详见[MCP 验证范围](mcp.md#7-实现与验证范围)。

仍需作者明确理解的限制：

1. token 估算是本地启发式；只有提供方返回 usage 时才有真实输入 / 输出 / 缓存统计。
2. 关键词检索可解释、可复现，但不是语义向量检索；资料多时应使用注入排序和上下文编排控制预算。
3. Agent 是“模型规划 + 本地校验 + 用户确认 + 本地执行”，不是无人值守的自主代理。
4. 模型能否支持结构化输出、流式和缓存统计取决于具体提供方；协议枚举不会替模型补齐缺失能力。
5. 网络热梗依赖搜索引擎、代理和上游网络状态；搜索失败时应显示错误，不创建虚假条目。
6. API Key 和应用状态保存在本机应用数据目录；该目录不应进入 Git，也不应在共享电脑上长期保留。

后续可以继续完善批处理预算与失败策略、生成与审核 API 分工、更加准确的 tokenizer、更多可解释检索方式和作品级工作记录导出，但这些都应在现有 `.qy` 版本和操作协议上增量演进。当前串行任务队列不意味着无人值守连续创作或完整 headless CLI 已经完成。
