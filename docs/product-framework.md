# 叙事工坊：当前产品与技术框架

日期：2026-10-05。状态：已落地的桌面端实现说明与数据契约。

本文档描述仓库当前已经实现的产品行为、数据边界和技术结构。它不是早期原型提案，也不承诺当前代码中不存在的数据库、云同步、多人协作或后台自主运行能力。界面和数据结构继续演进时，应先更新本文件，再更新 Agent 的 JSON 契约和测试。

## 1. 产品定位与运行边界

叙事工坊是一个本地优先的长篇小说创作工作台。作者以章节为中心写作，同时维护世界书、角色卡、道具卡、技能卡、大纲、世界引擎、文风规则、自定义模块和网络热梗。AI 负责生成候选内容、提出结构化修改计划和推演建议；作者决定是否采纳。

产品运行在 Electron 独立窗口中。Vue 3 + TypeScript + Vite 负责渲染，Electron 主进程负责无边框窗口、单实例、作品文件和生命周期，本机 Node HTTP 服务负责 JSON 状态持久化、模型代理和联网搜索。浏览器页面仍能作为开发 / 兼容预览运行，但完整产品边界以桌面端为准。

当前明确不包含：账号体系、云端同步、多人协作、SQLite / ORM 数据库、向量数据库、自动连续写完整本书、未确认状态自动写回作品，以及没有来源的隐式 Agent 操作。

## 2. 信息架构与布局

主界面使用单页导航，不使用 Vue Router。左侧大功能栏按以下分组排列：

1. **开始写作**：章节写作。
2. **创作空间**：世界书、角色卡、道具卡、技能卡、自定义模块、网络热梗。
3. **全局把握**：故事大纲、世界引擎。
4. **AI 功能**：AI Agent。
5. **全局功能**：文风规则。
6. **Debug**：上下文编排、JSON 结构查看器。

API 预设和软件设置从右上角的设置按钮打开，不占用主导航。桌面端使用自定义无边框标题栏，包含作品文件菜单、保存状态、夜间 / 白天切换、设置、最小化、最大化和关闭。

写作页采用“章节目录 + 正文编辑区 + 右侧任务 / 资料区”的布局。资料卡页采用“左侧条目 / 折叠栏 + 右侧详情编辑”的布局；左右栏分别滚动，避免操作一侧时另一侧跳动。Agent 悬浮球可自由拖动，弹出的 Agent 窗口跟随悬浮球位置。

## 3. 作品与全局数据边界

### 3.1 Store：作品内容

作品主体保存在 `Store` 中，主要结构如下：

| 数据 | 用途 |
| --- | --- |
| `volumes` / `chapters` | 分卷、章节、正文、状态、字数、任务目标和出场人物 |
| `world` | 世界书条目 |
| `characters` | 角色卡和角色持有关系、图片 |
| `items` | 道具卡 |
| `skills` | 技能卡 |
| `outline` | 全书、卷、章节范围和场景组成的嵌套大纲 |
| `style` | 文风规则；应用状态同时保留一份全局副本 |
| `worldEngine` | 世界时间、后台角色状态、关系、事件、时间线、笔记、提案和日志 |
| `customModules` | 自定义模块 schema 与具体条目 |
| `memes` | 网络热梗专表 |
| `contextGroups` / `contextBlocks` | 两级提示词编排布局和兼容投影 |
| `resourceGroups` | 世界书、角色、道具、技能、文风的折叠栏顺序 |
| `providers` / `modelOptions` | API 预设和模型列表；属于应用级配置，`.qy` 不导出 |

每个标准资料条目使用稳定 `id`、显示名称、摘要、字段字典、检索设置、注入排序、锁定字段和校对元数据。字段字典保留中文字段名作为提示词契约的可读键名。

### 3.2 全局设置

以下内容跨作品保存：API 预设、模型列表、自动保存间隔、Agent 修改历史上限、`.qy` 备份数量、主题颜色、格式化缩进和全局文风规则。作品切换或新建只替换作品快照，不应覆盖这些设置。

Agent 对话、活动日志、修改历史和撤销快照属于本机应用状态。它们能随当前作品在本机恢复，但目前不写入 `.qy` 文件；迁移作品时需要一并保留应用数据目录，才能保留这些工作记录。

## 4. 作品文件、持久化与恢复

### 4.1 `.qy` 文件

`.qy` 是版本化 JSON 文件，当前格式为：

```json
{
  "format": "qy",
  "version": 1,
  "title": "作品名",
  "updatedAt": 0,
  "content": { "chapters": [], "volumes": [], "world": [] }
}
```

`content` 保存章节、分卷、世界书、角色、道具、技能、大纲、世界引擎、自定义模块、网络热梗、文风和上下文布局。它不保存 API Key、API 预设、模型列表、主题、自动保存间隔和备份数量。导入时先校验 `format`、`version`、章节和分卷数组，再合并到当前应用状态；API 等应用级配置始终保留当前本机版本。

文件菜单支持新建、打开、打开最近文件、保存和另存为。保存前可按设置把旧文件旋转到备份目录，并删除超出数量的旧备份。最近文件最多显示 30 条。桌面端启动会尝试打开最近文件；没有最近文件或文件不可读时，应用保持空白作品，不用示例 seed 覆盖用户文件。

### 4.2 本机状态服务

Electron 在 `userData` 下启动绑定 `127.0.0.1` 的 Node 服务，状态文件使用临时文件写入再原子替换。`PUT /api/storage` 携带 `expectedUpdatedAt`，版本不一致时返回冲突并暂停保存，避免两个窗口静默覆盖内容。

自动保存由设置中的 0 / 5 / 10 / 30 / 60 / 300 秒间隔控制。关闭窗口时，主进程会要求渲染器完成最后一次刷盘；保存失败会给出“返回应用”或“放弃保存并退出”的选择。Electron 使用单实例锁，重复启动会恢复、显示并聚焦已有窗口，包括最小化窗口。

## 5. 标准资料模型

### 5.1 世界书、角色、道具和技能

四类标准资料都支持：名称、摘要 / 内容、触发策略、触发键、递归选项、注入排序、分组和锁定状态。触发策略是 `关键词` 或 `常驻`，默认是关键词；角色、道具和技能没有手动触发键时使用自身名称作为默认触发词。递归和进一步递归默认关闭。

角色卡额外包含角色身份（主角 / 配角 / 路人）、性别、种族、性格、外貌、人物信息、动态状态、持有道具和持有技能。持有物品和技能以标签显示，可以通过加号关联现有卡片，并点击标签查看详情。角色图片独立于 AI 上下文，支持多图、裁切、9:16 竖向封面、设为封面和删除。

技能卡的性质只有主动 / 被动两项；技能效果使用可伸缩输入。道具卡保存用途、持有人、位置、限制、正文证据和关联线索等字段。标准卡都支持结构编辑模式：作者可以预览发给 AI 的通用 JSON 结构，并编辑整类卡片的“强化提示词”。强化提示词用于 Agent 创建这类卡片时解释字段含义，不会被当成每个已有条目的独立内容。

### 5.2 文风规则

文风规则是全局创作约束，不依赖作品切换。规则支持启用开关、折叠栏、拖动排序、规则内容、正例、反例和整体强化提示词。写作模式会把启用的规则作为底层提示词，用于正文、世界书、角色、道具、技能和自定义模块的创作；灵感模式可以不受文风约束，但仍读取世界资料。

### 5.3 大纲

大纲层级为：

```text
全书
└── 卷
    └── 章节范围
        └── 场景
```

父子类型和循环关系在本地校验。卷、章节范围和场景可以折叠，节点包含目标、冲突、关键转折、结尾状态、视角 / 地点和章节范围等字段。世界引擎读取大纲作为剧情目标和因果约束；旧的“伏笔”大栏目不再作为独立数据源。

## 6. 检索与上下文编排

### 6.1 确定性检索

当前检索只使用常驻 / 关键词策略，不使用向量检索或随机触发。检索输入来自当前章节标题、任务目标、正文、出场人物和 Agent 当前需求。结果来自世界书、角色、道具、技能、大纲和文风条目。

检索流程：

1. 先选出常驻条目和直接关键词命中的条目。
2. 根据条目的递归开关，从条目内容和字段中继续匹配其他条目。
3. 使用最大递归深度和结果数量上限，避免一次请求膨胀。
4. 按注入排序、递归深度和原始顺序稳定排序。
5. 将命中条目、命中键、深度和顺序格式化为提示词资料。

所有新建标准卡的递归字段默认关闭。检索不会因为条目被找到就改变条目内容，也不会把模型的推测当作确认事实。

### 6.2 两级上下文布局

上下文编排使用“提示大类 → 大类内资料项”的两级结构。当前大类包括系统约束、世界书、角色卡、道具卡、技能卡、文风规则、自定义模块、世界引擎、大纲 / 本章任务、近期正文和输出要求。大类和条目都可以启用、禁用、折叠和拖动。

布局顺序就是组装提示词时的顺序。自定义模块也属于可编排资料，不再作为隐藏的单独通道。正文、Agent 和世界引擎共用这套布局，但每个调用会根据自身检索结果选择实际条目。

上下文 token 在资料内容或布局发生变化时重新估算，不再只读取初始化时的旧 `tokens` 值。估算值用于本地预算提示；模型实际返回的 usage 单独显示，缺少提供方字段时保持未知。

## 7. AI Agent 协议与安全边界

### 7.1 两种模式

- **写作模式**：所有创作性回复、正文和资料文字都必须遵守启用的文风规则。
- **灵感模式**：可以自由讨论剧情和发散想法，不强制套用文风规则；仍须把检索资料视为事实边界，明确区分推测和确认状态。

两种模式都会读取当前章节、上下文检索包、世界引擎状态、自定义模块契约、网络热梗和最近 Agent 对话历史。聊天历史用于理解前后文，不能替代作品数据。

### 7.2 JSON 操作协议

Agent 必须返回：

```json
{
  "message": "给作者看的简短结果",
  "operations": []
}
```

当前操作包括：

- 搜索网络热梗；
- 创建 / 更新世界书、角色、道具、技能、大纲、世界引擎事件和文风规则；
- 创建章节和分卷，追加章节正文；
- 创建、删除和移动世界书 / 角色 / 道具 / 技能 / 文风折叠栏；
- 创建自定义模块 schema，创建 / 更新 / 删除自定义模块条目。

标准资源创建必须使用完整模板字段；更新只允许写目标条目已有的标准字段，不允许借机创建独立的自定义结构。需要新的结构时必须使用 `create_custom_module`，再用对应的条目操作写入数据。这条边界用于避免模型把一个道具误拆成多个世界书条目。

### 7.3 计划、确认、锁和撤销

Agent 先生成操作计划和可读描述。作者确认后，前端再次校验目标、字段和引用，再执行操作。锁定字段、校对状态锁和整条目大锁会阻止对应修改；整条目解锁时会同步恢复字段锁状态。

每次 Agent 执行都会保存前后快照、摘要和变更列表。只有最近一笔、且作品之后没有发生冲突修改的操作可以直接撤销。对话、活动日志和修改记录可以在设置中限制保留数量。Agent 不是后台持续自主运行的进程，所有写入都经过当前窗口的本地操作执行器。

## 8. 世界引擎

世界引擎全面接管旧伏笔功能。它读取大纲、正文、检索到的世界资料和已确认的角色 / 道具 / 技能状态，输出可审阅的世界变化：

- 天下大势、事件链和后果；
- 主角与配角的行动、关系和下一步目标；
- 时间线、工作笔记和线索状态；
- 可以提供给正文与 Agent 的已确认世界状态。

路人角色不会自动进入关系推演。推演时间通过当前、按章、按天、按月和自定义天数推进；自定义时间只表示推进若干天，不使用分钟级自动推进。世界引擎可以选择不同于主线写作的 API。推演结果先进入待确认提案，作者确认 / 拒绝后才更新正式状态。

## 9. 自定义模块与网络热梗

### 9.1 自定义模块

自定义模块是实验性但可持久化的结构编辑器。作者先定义模块类型、描述和字段，再创建具体条目。字段类型包括：

```text
string / text / longText / number / enum / boolean / tags
characterIndex / itemIndex / skillIndex
```

每个字段有 key、标签、描述、默认值、枚举选项、必填状态、锁定状态和强化提示词。引用字段存稳定卡片 ID，界面显示为可点击标签；删除被引用卡片时，完整性清理会移除无效引用。

Agent 可以读取模块 schema、JSON 契约、示例和现有条目，也可以在用户确认后创建 / 更新 / 删除模块条目。标准资源和自定义模块使用不同的操作类型，避免结构串栏。

### 9.2 网络热梗

网络热梗使用独立的 `MemeStore`，字段包括名称、含义、适用场景、例句、来源、日期、关键词、启用、锁定、创建来源和校对状态。Agent 不能把网络热梗写成世界书条目。

收到搜索需求后，Agent 应返回 `search_web_memes` 操作。桌面端会把自然语言拆成若干查询，按选定的 Bing、Google 或 DuckDuckGo 分批搜索，去重后再调用整理流程提炼名称、表达、含义和使用场景，最后写入热梗表。搜索候选和已保存条目可以在热梗页面本地搜索和管理。

## 10. API、模型和本机代理

API 预设由右上角设置面板管理，协议枚举为：

```text
OpenAI Compatible / Anthropic / Google Gemini / 自定义 HTTP
```

默认协议是 OpenAI Compatible。预设可以启用为默认 API；正文、Agent 和世界引擎可分别选择 API。模型列表通过本机服务从当前地址拉取，界面使用下拉栏选择模型；不支持列表的服务可以手动填写模型。

每个预设可配置：

- Base URL、API Key、模型和连接状态；
- 上下文长度、最大输出、历史预算；
- 温度、Top P、频率惩罚、存在惩罚；
- 流式输出和流式 usage 统计；
- 上游 HTTP 代理地址、端口、协议、用户名和密码；
- 输出 token 参数（`max_tokens` 或 `max_completion_tokens`）。

服务端按协议转换请求和流式响应，支持 SSE 增量、取消、空闲超时、错误脱敏和 usage 归一化。Gemini 的模型列表、请求和 usage 使用其原生字段；Anthropic 的不支持参数会在发送前拒绝。服务端未返回上下文窗口或缓存数据时，界面不会伪造精确值。

## 11. 主题、设置与桌面生命周期

主题设置分别保存白天和夜间调色板，每套包含主色 / 背景、次配色、按钮、字体、成功、危险、提醒和信息颜色。界面组件使用主题变量，不应直接写死状态色或标题色。设置还包括自动保存、Agent 历史上限、`.qy` 备份数量、格式化缩进和归档 Agent 对话管理。

Electron 主进程使用单实例锁、启动日志和独立可写的 Chromium session/cache 目录。窗口渲染失败、加载失败、本机服务失败和保存失败都会记录诊断信息；应用不会在本机状态服务不可用时用示例内容覆盖用户作品。

## 12. 代码结构

```text
src/
  App.vue                       页面组合、作品状态、持久化和业务动作
  components/                   写作、资料卡、Agent、设置、世界引擎和 Debug 面板
  agent/                        JSON schema、校验、操作执行、聊天历史
  api/                          模型请求、上下文预算、usage、模型上限
  context/                      常驻 / 关键词检索和提示资料格式化
  data/                         seed、迁移、主题、世界引擎、自定义模块、热梗、.qy
  composables/                  写作、章节、段落修改和世界引擎控制器
  types.ts                      Store、资源、上下文和 Agent 类型
electron/
  main.mjs                      桌面窗口、单实例、.qy 文件和本机服务生命周期
  preload.cjs                   contextIsolation 下的最小桌面 API 桥
server/
  index.mjs                     JSON 存储、模型代理、SSE、模型上限和联网搜索
test/
  *.test.mjs                    Agent、检索、写作、上下文、世界引擎和服务端测试
```

当前项目是单个 npm 包，不使用 pnpm workspace、Vue Router、Pinia、Tailwind、shadcn、Fastify、SQLite、Prisma 或 Tiptap。后续若引入这些组件，应在技术迁移文档中明确数据迁移和行为变化，不能把规划栈当成当前实现。

## 13. 验证与已知限制

提交前至少运行：

```bash
npm run build
npm test
```

当前测试覆盖 Agent 操作与校验、标准资源结构、上下文预算与布局、章节和段落编辑、写作生成、世界引擎、模型上限、流式聊天、服务端存储和安全边界。

仍需作者明确理解的限制：

1. token 估算是本地启发式；只有提供方返回 usage 时才有真实输入 / 输出 / 缓存统计。
2. 关键词检索可解释、可复现，但不是语义向量检索；资料多时应使用注入排序和上下文编排控制预算。
3. Agent 是“模型规划 + 本地校验 + 用户确认 + 本地执行”，不是无人值守的自主代理。
4. 模型能否支持结构化输出、流式和缓存统计取决于具体提供方；协议枚举不会替模型补齐缺失能力。
5. 网络热梗依赖搜索引擎、代理和上游网络状态；搜索失败时应显示错误，不创建虚假条目。
6. API Key 和应用状态保存在本机应用数据目录；该目录不应进入 Git，也不应在共享电脑上长期保留。

后续可以继续完善批量 Agent 任务队列、内容审核 API、更加准确的 tokenizer、更多可解释检索方式和作品级工作记录导出，但这些都应在现有 `.qy` 版本和操作协议上增量演进。
